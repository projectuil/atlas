**Pattern**

Modern web services rarely operate independently. Instead, they depend on interconnected external systems, creating relationships that remain largely invisible to users. Web applications rely on third-party scripts, analytics engines, single sign-on providers, payment gateways, external CDNs, and data brokers to deliver functionality.

This pattern demonstrates how architectural interdependencies obscure system behavior. When a third-party dependency degrades, or data is passed silently across server boundaries, users struggle to comprehend why a local action failed or how their personal data reached an external platform, resulting in complete opacity regarding service boundaries.

**Human Impact**

*   Inability to troubleshoot partial site failures caused by third-party outages.
*   Mistrust caused by unexpected data-sharing between independent web tools.
*   Disorientation when browser extensions or external scripts break core web features.
*   Misplacing blame on primary websites when third-party microservices crash.
*   Helplessness when federated login integrations fail to communicate.

**Evidence**

This Pattern is currently supported by the following Human Frictions:

*   **WI-020** – Users struggle to complete tasks because information and actions are distributed across multiple websites.
*   **WI-044** – Users struggle to understand how websites share information with external services.
*   **WI-045** – Users struggle to understand how third-party services influence website functionality.
*   **WI-047** – Users struggle to understand the relationship between browsers, websites, extensions, and web applications.
*   **WI-050** – Users gradually lose awareness of how their online identity becomes distributed across interconnected web services.

Across these observations, hidden third-party infrastructure dependencies prevent users from developing an accurate mental model of web functionality.

**Research Notes**

Highlights the complexity of the modular web stack. Future research should evaluate how clear component boundaries and architectural transparency can help users diagnose failures and audit data flows.
