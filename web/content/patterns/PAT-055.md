**Pattern**

Users repeatedly evaluate and verify identity before trusting authentication requests, verification methods, and security events.

This pattern describes the cognitive processes and decisions users undergo when presented with identity checks, security prompts, or unprompted verification requests, navigating the fine line between authentic system operations and malicious attempts.

**Human Impact**

*   Hesitation and cognitive load during identity verification events.
*   Vulnerability to social engineering, phishing, and push notification fatigue attacks.
*   Alert fatigue leading to automatic, unverified prompt approvals.
*   Confusion caused by missing or ambiguous context in security alerts.
*   Perceiving legitimate step-up security prompts as system failures.

**Evidence**

This Pattern is currently supported by the following Human Frictions:

*   **AU-004** — Users struggle to understand complex multi-factor authentication (MFA) prompts.
*   **AU-018** — Users struggle to distinguish legitimate security prompts from malicious requests.
*   **AU-034** — Users struggle to understand why repeated identity verification is required for sensitive actions.
*   **AU-035** — Users struggle to recognize fraudulent authentication requests and social engineering attempts.
*   **AU-040** — Users struggle to identify which authentication requests originate from trusted systems.
*   **AU-047** — Users struggle to determine which authentication events require immediate security action.

Across these observations, the recurring relationship is the continuous cognitive evaluation required when interacting with system security challenges and notifications.

**Research Notes**

Evidence emphasizes that standard security verification mechanics often fail to give users sufficient contextual data (such as clear location, domain, or app metadata) needed to make safe, informed choices.

Future validation should explore how contextual MFA (e.g., number-matching, explicit app-origin indicators) reduces evaluation errors.
