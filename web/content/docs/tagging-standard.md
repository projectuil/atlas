__ Project UIL__

__ATLAS Taxonomy__

__Document 06 - Tagging Standard__

__Version 1\.0__

__1\. Purpose__

The Tagging Standard defines how descriptive keywords are assigned to research entities within the ATLAS Research Repository\.

Its purpose is to improve:

- Searchability 
- Discoverability 
- Cross\-category analysis 
- Pattern identification 
- Future automation 

Tags complement categories but never replace them\.

__2\. Core Principle__

__Categories organize\. Tags describe\.__

A Human Friction belongs to __one primary category__, but it may have __multiple tags__ that describe different aspects of the problem\.

__3\. Why Tags Exist__

Tags help answer questions that categories cannot\.

Example:

Human Friction:

Downloaded files are difficult to locate after downloading\.

Category:

Files & Folders

Tags:

Search

Navigation

Downloads

Memory

Desktop

Now researchers can search for every Human Friction related to __Memory__, even if they belong to different categories\.

__4\. Tagging Principles__

Every tag should be:

__Descriptive__

Describe the friction\.

__Good__

Navigation

Search

Memory

__Bad__

Fix

Issue

Problem

__Reusable__

Tags should be standardized\.

Don't create:

Searching

Searching Files

Search Feature

Searching Folder

Instead:

Search

__Technology Independent__

Avoid:

Chrome

Windows Explorer

Google Drive

Prefer:

Browser

File Management

Cloud Storage

__Consistent__

Always use the same spelling and capitalization\.

Example:

Knowledge Management

Not:

Knowledge management

knowledge\-management

KnowledgeMgmt

__5\. Tag Categories__

ATLAS organizes tags into logical groups\.

__Functional Tags__

Describe the type of activity\.

Examples:

Search

Navigation

Authentication

Communication

Collaboration

Learning

__Cognitive Tags__

Describe human thinking\.

Examples:

Memory

Attention

Decision Making

Cognitive Load

Context Switching

__Environment Tags__

Describe where the friction occurs\.

Examples:

Desktop

Mobile

Web

Physical

Hybrid

__Behaviour Tags__

Describe user behaviour\.

Examples:

Habit

Confusion

Forgetting

Interruptions

Distraction

__Research Tags__

Used internally\.

Examples:

High Priority

Needs Validation

Pattern Candidate

Research Gap

Duplicate Review

__6\. Tag Assignment Rules__

Every Human Friction:

- Must have at least __2 tags__\. 
- Should generally have __3-7 tags__\. 
- Should avoid unnecessary or repetitive tags\. 

Tags should describe the Human Friction from different perspectives\.

__7\. Tag Naming Rules__

Tags should:

- Use Title Case\. 
- Be singular unless naturally plural\. 
- Avoid abbreviations\. 
- Be concise\. 

Examples:

Memory

__Yes__

Navigation

Decision Making

__No__

Memories

Nav

Decisions

__8\. Tag Relationships__

Tags are independent\.

The same tag may appear across multiple categories\.

Example:

Memory

may exist in:

- Files & Folders 
- Learning 
- Authentication 
- Communication 

This allows cross\-domain analysis\.

__9\. Reserved Tags__

Certain tags are reserved for ATLAS governance\.

Examples:

Needs Review

Archived

Pattern Candidate

High Priority

Duplicate

These should not be used as descriptive tags\.

__10\. Tag Lifecycle__

Tags may evolve over time\.

Possible statuses:

- Proposed 
- Active 
- Deprecated 
- Merged 

Deprecated tags remain documented for historical consistency\.

__11\. Tag Registry__

__12\. Future Applications__

A standardized tagging system enables:

- Fast repository search 
- Pattern discovery 
- Trend analysis 
- Visualization dashboards 
- AI\-assisted research 
- Recommendation systems 

__13\. Final Principle__

__Categories define where a Human Friction belongs\. Tags reveal what it is about\. Together they create a richer and more discoverable research ecosystem\.__
