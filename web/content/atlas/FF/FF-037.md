Projects often contain numerous files that serve different purposes, including documentation, source files, configuration files, reference materials, and supporting resources. Users revisiting a project frequently struggle to determine which file should be opened first to understand the project and resume meaningful work.

**Human Impact**

*   Slower project onboarding.
*   Interrupted workflow.
*   Increased cognitive effort.
*   Delayed task resumption.
*   Reduced productivity.

**Context**

Commonly occurs in:

*   Software repositories.
*   Research repositories.
*   Academic projects.
*   Business documentation.
*   Collaborative workspaces.

**Evidence / Observation**

This behaviour is consistently observed when users return to existing projects after a period of inactivity or when accessing projects created by others. Although all project files remain available, users often spend considerable time determining the appropriate entry point because traditional file systems organize files without identifying where project understanding should begin.

**Research Notes**

*   Contributes to **PAT-003 — Relationship Blindness.**
*   Highlights the absence of an explicit project entry point.
*   Related to project navigation, workflow continuity, and knowledge organization.
