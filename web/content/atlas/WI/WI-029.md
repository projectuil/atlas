To mitigate security risks, websites enforce automated session timeouts, token revocations, and cookie expiration policies. However, because platforms rarely notify users _why_ an active session ended—whether due to inactivity, IP change, security policy, or browser cookie clearing—users experience unexpected logouts as arbitrary system failures.

**Human Impact**

*   Interruption of active tasks and loss of unsaved input data.
*   Irritation and friction re-authenticating repeatedly during work sessions.
*   Misinterpretation of routine security timeouts as account compromise or site bugs.
*   Reluctance to leave web tools open for long-duration tasks.

**Context**

Commonly occurs when:

*   Working inside banking, financial, or healthcare portals during intermittent research.
*   Leaving enterprise web tools open overnight or across weekend breaks.
*   Switching network connections (e.g., disconnecting from office VPN to home Wi-Fi).

**Evidence / Observation**

Users frequently express shock and annoyance when submitting a completed web form yields a redirection to a blank login page. Non-technical users often assume their password was stolen or that the web service crashed, rather than recognizing a standardized security session expiration protocol.

**Research Notes**

*   Focuses on the friction caused by invisible background security policies.
*   Demonstrates the trade-off between strict cybersecurity compliance and continuous user experience.
*   Connects to task persistence (WI-022) and cookie mechanisms (WI-037).
