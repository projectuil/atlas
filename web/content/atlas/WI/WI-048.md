Standard browser designs prioritize continuous session persistence, password auto-saving, and history autocomplete for single-user devices. When operating on shared, public, or library computers, these default persistence mechanisms expose personal accounts, search histories, and auth tokens to subsequent users if explicit logouts are forgotten.

**Human Impact**

*   Severe account hijacking risks when leaving sessions active on shared hardware.
*   Exposure of personal credentials, search history, and private files to strangers.
*   False sense of security provided by misunderstanding "Incognito Mode."
*   Stress and paranoia after using public terminal infrastructure.

**Context**

Commonly occurs when:

*   Accessing webmail, banking, or travel documents at hotel business centers or public libraries.
*   Using shared family computers where multiple users browse on a single OS profile.
*   Logging into work accounts on personal or temporary device hardware.

**Evidence / Observation**

Observational field studies at public terminals reveal that users routinely close browser windows assuming that closing the app logs them out of active accounts. Subsequent users reopening the browser frequently discover active, fully authenticated sessions on webmail or social accounts because cookies persisted across window sessions.

**Research Notes**

*   Highlights the failure of browser default settings in multi-user physical environments.
*   Demonstrates widespread user misunderstanding of Incognito/Private mode protections.
*   Essential foundation for Shared Terminal Vulnerability and Persistence Friction.
