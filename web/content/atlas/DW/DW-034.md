Primary tasks (writing, design, coding) frequently require concurrent access to supporting documentation (specifications, notes, wireframes). Desktop environments treat reference windows identically to primary work windows, forcing users to manually position and resize supporting assets alongside primary editors without dedicated dockable or contextual reference panes.

**Human Impact**

*   Inefficient display layout resulting in squeezed or cut-off reference text.
*   Constant manual adjustments to keep reference documents visible.
*   Visual fatigue from juggling primary and secondary work zones.

**Context**

Commonly occurs when:

*   Writing reports based on research papers or spreadsheets.
*   Developing software while referencing API documentation and UI designs.

**Evidence / Observation**

Users dedicate up to half their display area to a static document, yet must constantly scroll or resize it because standard windows are not optimized for passive reference viewing.

**Research Notes**

*   Explores the functional distinction between active authoring spaces and passive reference spaces.
