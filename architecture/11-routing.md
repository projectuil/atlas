# 11 — Routing

This document explains the complete URL structure of the UIL web application, the routing rules for each route, how static paths are generated, and the conventions used in the Next.js App Router.

---

## Router Overview

The application uses the **Next.js App Router** (introduced in Next.js 13), where each `page.tsx` file defines a route. All routes are rendered at build time via `output: 'export'`.

```
app/
├── layout.tsx              → Shared layout (all routes)
├── page.tsx                → /
├── atlas/
│   ├── page.tsx            → /atlas
│   └── [slug]/page.tsx     → /atlas/:slug
├── patterns/
│   ├── page.tsx            → /patterns
│   ├── [slug]/page.tsx     → /patterns/:slug
│   └── volume/
│       └── [slug]/page.tsx → /patterns/volume/:slug
├── docs/
│   └── [[...slug]]/page.tsx → /docs  AND  /docs/:slug
├── metrics/
│   ├── page.tsx            → /metrics
│   ├── frictions/page.tsx  → /metrics/frictions
│   └── patterns/page.tsx   → /metrics/patterns
└── registries/
    ├── page.tsx            → /registries
    ├── apid/page.tsx       → /registries/apid
    ├── category/page.tsx   → /registries/category
    ├── pattern/page.tsx    → /registries/pattern
    └── [slug]/page.tsx     → /registries/:slug
```

## Dynamic Routes

### `/atlas/[slug]` — The Polymorphic Route

**File**: `app/atlas/[slug]/page.tsx`

This single route handles two completely different content types:

#### Type 1: Category Pages
URL pattern: `/atlas/<domain-code>` (e.g., `/atlas/au`, `/atlas/ff`)

Renders the `<CategoryClient />` component with all frictions in that domain.

#### Type 2: Friction Detail Pages
URL pattern: `/atlas/<apid>` (e.g., `/atlas/au-001`, `/atlas/wi-045`)

Renders a static friction dossier SSR page.

**Disambiguation Logic**:
```typescript
const isCategory = categories.some(c =>
  c.code.toLowerCase() === slug.toLowerCase()
);
```

A slug is a category page if it exactly matches a known domain code (lowercase). Otherwise it falls through to friction lookup.

**Static Params Generation**:
```typescript
export async function generateStaticParams() {
  const frictions = getFrictions();
  const categories = getCategories();
  
  return [
    ...categories.map(c => ({ slug: c.code.toLowerCase() })),
    ...frictions
      .filter(f => f.identity?.apid)
      .map(f => ({ slug: f.identity.apid.toLowerCase() }))
  ];
}
```

This generates: `au`, `dw`, `ff`, `ki`, `le`, `mb`, `os`, `wi`, `au-001`, `au-002`, ... (up to ~400 routes).

### `/patterns/[slug]` — Pattern Detail

**File**: `app/patterns/[slug]/page.tsx`

URL pattern: `/patterns/pat-001`, `/patterns/pat-064`

**Static Params Generation**:
```typescript
export async function generateStaticParams() {
  const patterns = getPatterns();
  return patterns
    .filter(p => p.identity?.id)
    .map(p => ({ slug: p.identity.id.toLowerCase() }));
}
```

Generates: `pat-001`, `pat-002`, ... `pat-064` (or however many patterns exist).

---

### `/patterns/volume/[slug]` — Volume Group

**File**: `app/patterns/volume/[slug]/page.tsx`

URL pattern: `/patterns/volume/volume-01-cognitive-behaviour`

Slugs are generated by converting volume names to URL-safe strings:
```typescript
const slug = volumeName
  .toLowerCase()
  .replace(/\s+/g, '-')
  .replace(/[^a-z0-9-]/g, '');
```

Note that em-dashes (`—`) are stripped because they are non-ASCII.

**Static Params Generation**:
```typescript
export async function generateStaticParams() {
  const volumeMap = getPatternsByVolume();
  return Object.keys(volumeMap).map(volume => ({
    slug: volume.toLowerCase().replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '')
  }));
}
```

---

### `/docs/[[...slug]]` — Documentation Catch-All

**File**: `app/docs/[[...slug]]/page.tsx`

The **optional catch-all** route `[[...slug]]` handles both the index and individual doc pages:

| URL | Behavior |
|-----|---------|
| `/docs` | Renders `<DocsClient />` (category-grouped card index) |
| `/docs/constitution` | Renders static doc prose with sidebar |
| `/docs/publishing-manual` | Renders static doc prose with sidebar |

The optional catch-all pattern means:
- When `slug` is `undefined` → renders the index
- When `slug` is `['constitution']` → renders that document

**Static Params Generation**:
```typescript
export async function generateStaticParams() {
  const docs = getDocs();
  return [
    { slug: [] },  // /docs index
    ...docs.map(doc => ({ slug: [doc.slug] }))
  ];
}
```

---

### `/registries/[slug]` — Generic Registry Fallback

**File**: `app/registries/[slug]/page.tsx`

A fallback for any registry URL that doesn't match `/apid`, `/category`, or `/pattern`. Renders the registry document as plain Markdown prose (no interactive features).

**Static Params Generation**:
```typescript
export async function generateStaticParams() {
  const registries = getRegistries();
  return registries.map(r => ({ slug: r.slug }));
}
```

## URL Convention Rules

| Convention | Example | Rule |
|-----------|---------|------|
| APIDs in URLs | `/atlas/au-001` | Always lowercase |
| Domain codes in URLs | `/atlas/au` | Always lowercase |
| PAT IDs in URLs | `/patterns/pat-001` | Always lowercase |
| Volume slugs | `/patterns/volume/volume-01` | Lowercase, hyphens, ASCII only |
| Doc slugs | `/docs/constitution` | From frontmatter `slug` field |
| Registry slugs | `/registries/apid` | Fixed (hardcoded paths) |

---

## Route Priority

In the App Router, more specific routes take priority over less specific ones. In UIL:

- `/registries/apid` → matches `registries/apid/page.tsx` (specific)
- `/registries/category` → matches `registries/category/page.tsx` (specific)
- `/registries/anything-else` → matches `registries/[slug]/page.tsx` (dynamic)

Similarly for docs:
- `/docs` → matches `docs/[[...slug]]/page.tsx` with empty slug
- `/docs/constitution` → same file with `['constitution']` slug

The `[slug]` pattern is more specific than `[[...slug]]` in the same directory, but since there's only one file in `docs/`, there's no ambiguity.

---

## Not Found Handling

The static export does not have a built-in 404 page mechanism unless a `not-found.tsx` or custom `404.html` is provided. Without this:

- Navigating to a non-existent URL produces a hosting-level 404 (behavior depends on the static host)
- Parameterized routes only pre-render the slugs declared in `generateStaticParams()` — any other slug produces a 404

There is currently no `not-found.tsx` defined, so 404 pages are handled by the web host's default behavior.

## Homepage Route

**File**: `app/page.tsx`

The homepage is a Server Component that renders:
- Hero section with project tagline
- Live stats (total frictions, patterns, docs from API calls)
- Domain card grid (8 categories, mirroring Atlas Explorer)
- "How it works" workflow visualization
- "Recent Research" section with featured frictions/patterns
- Call-to-action cards to major sections

All data is fetched at build time via `getFrictions()`, `getPatterns()`, `getDocs()`.

```
/                           ← getFrictions(), getPatterns(), getDocs(), getCategories()
/atlas                      ← getCategories(), getFrictions() (for count)
/atlas/au                   ← getCategories(), getFrictionsByCategory('AU')
/atlas/au-001               ← getFrictions(), getPatterns() (for related backlinks)
/patterns                   ← getPatterns(), getPatternsByVolume()
/patterns/pat-001           ← getPatterns(), getFrictions() (for related backlinks)
/patterns/volume/volume-01  ← getPatterns() (filtered by volume)
/docs                       ← getDocs()
/docs/constitution          ← getDocs() (single doc by slug)
/metrics                    ← (static, no API calls needed)
/metrics/frictions          ← getFrictions(), getPatterns() (for live count interpolation)
/metrics/patterns           ← getPatterns() (for live count interpolation)
/registries                 ← getFrictions(), getPatterns() (for count display)
/registries/apid            ← direct fs.readFileSync, parseRegistryDocument()
/registries/category        ← direct fs.readFileSync, parseRegistryDocument()
/registries/pattern         ← direct fs.readFileSync, parseRegistryDocument()
```
