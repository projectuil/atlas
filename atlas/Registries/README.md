# ATLAS Registries

The **Registries** folder contains the master indexes of the ATLAS repository.

Unlike research documents, registries do not contain observations or analysis. Instead, they provide a centralized reference for tracking and organizing the core entities that exist within ATLAS.

Registries help maintain consistency, prevent duplication, and make the repository easier to navigate as it grows.

---

# Registry Overview

## APID Registry

The master index of all documented Human Frictions.

This registry records:

- Atlas Problem Identifiers (APIDs)
- Human Friction titles
- Categories
- Documentation status

Every accepted Human Friction should be registered here.

---

## Category Registry

The master index of all official ATLAS categories.

This registry records:

- Category identifiers
- Category prefixes
- Category names
- Domain classifications
- Category status

It serves as the official reference for the ATLAS taxonomy.

---

## Pattern Registry

The master index of all documented Patterns.

This registry records:

- Pattern identifiers (PTIDs)
- Pattern titles
- Research categories
- Validation status

Every documented Pattern should be registered here.

---

# Registry Usage

Whenever a new repository entity is officially created:

- Register new Human Frictions in the APID Registry.
- Register new Categories in the Category Registry.
- Register new Patterns in the Pattern Registry.

Registries should always reflect the current state of the repository.

---

# Guiding Principles

Registries are indexes, not research documents.

They exist to answer **what has been documented**, not to explain or analyze the research itself.

All detailed information should remain in the corresponding Human Friction, Pattern, Research Insight, or Research Paper documents.
